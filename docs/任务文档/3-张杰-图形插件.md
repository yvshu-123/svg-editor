现有实现（迁移时照抄的地方）：

| 文件 | 内容 |
|---|---|
| `src/shapes/ShapeFactory.ts` | `registerBuiltins()` 里六种图形的构造闭包：参数个数校验、`svgAttributes` 顺序、`hasTextContent` |
| `src/domain/Rect.ts` `Circle.ts` `Ellipse.ts` `Line.ts` `TextShape.ts` `Group.ts` | 六个图形类，**类本身不动，只换注册方式** |

| `src/domain/Document.ts` | `add()` 先 `collectIds` 查全树再插入 → **整个子树一次性加入是原子的** |
| `src/io/SvgReader.ts` / `SvgWriter.ts` | 读写都经过 `ShapeFactory`，`data-kind` 要在这里落地 |

接口由农权淳提供（`ShapeProvider`、`AttributeHandler`、`Shape.onDetach`、`canUngroup`、`data-kind`），D2 给草案、D4 冻结。D1–D3 可以先用本地 stub 并行写。

## 2. 任务

| # | 任务 | 内容 | 完成标准 |
|---|---|---|---|
| S1 | 六图形插件化 | 把 `registerBuiltins()` 的六个闭包搬成六个包：参数校验文案、`svgAttributes` 顺序、`hasTextContent` 一字不改 | 迁走后 Phase 1 全会话输出逐字节不变 |
| S2 | `box` 图形 | `BoxShape extends Group`（复用 children/move/scale），`kind='box'`；`create box n1 120 100 160 60 "开始"`；子节点 `<id>-rect` + `<id>-label`；支持 `in`、整体 `move`/`scale`、可嵌套 | box 会话完整复现；`tree` 层级为 `box#n1` → `rect#n1-rect` / `text#n1-label` |
| S3 | `box` 原子创建 | 先构造含子节点的整棵树，再**一次** `document.add(box)`（Document 会先查全树 id 再插入） | 若 `n1-rect` 已被占用，报错后 `tree` 与创建前完全一致，无残骸 |
| S4 | 读回与降级 | `SvgWriter` 写 `data-kind="box"`；`SvgReader` 读到 `box` 且插件未装 → 普通 `g`；已装但缺子部件/类型错 → 拒绝整个读入或警告降级（ADR 定一种）；重复 id 必须拒绝整个读入 | 装/不装插件读同一文件：`box` / `g`，都不崩；坏 box 不产生半成品 |
| S5 | 子部件保护 | 实现 `Shape.onDetach()`：`-rect`/`-label` 被 `delete` 或 `move` 移出时抛错；实现 `canUngroup() = false` | `delete n1-rect`、`move n1-rect ...`、`ungroup n1` 都被拒并给明确错误 |
| S6 | `box` 属性处理器 | `handles` 判断：`kind === 'box'` 且属性是 `fill` 或 `label`；`apply`：`fill` → 内部矩形 `setAttribute('fill')`，`label` → 内部文本 `setAttribute('text')` | `set n1 fill #f5a623`、`set n1 label "处理数据 v2"` 生效，且各为一个 undo 单元 |
| S7 | ADR 与测试 | id 派生规则、读回降级策略、子部件保护策略；测试用替身 context，不依赖其它插件 | `npx vitest run plugins/shape-box` 全绿 |

## 3. 自验清单

- [ ] `npm run cli < doc/transcript/cli-1.txt` 与 `final` 的输出逐字节一致
- [ ] box 会话回放：`create box n1 …` → `tree` → `in` 嵌套 → `move` → `set fill` → `set label` → `undo` ×2
- [ ] `tree` 里 `g#n1` 变成 `box#n1`，两个子节点 id 为 `n1-rect`、`n1-label`
- [ ] 先 `create rect n1-rect …` 再 `create box n1 …`：报错，且 `tree` 与创建前一致
- [ ] `ungroup n1`：被拒
- [ ] `delete n1-rect`、`move n1-rect 10 10`：被拒
- [ ] `set n1 fill #f5a623` 一次 `undo` 整体回退，一次 `redo` 整体恢复
- [ ] `set n1 label "处理数据 v2"` 同上
- [ ] 写出一份含 `data-kind="box"` 的 SVG；禁用 box 插件后 `read` 它 → 得到普通 `g`，不崩

## 5. 容易踩的坑

1. **`Group.clone()` 返回的是 `Group`，不是 `BoxShape`**。`box` 必须 `override clone()`，否则一旦 `undo` 走快照恢复，`box` 会悄悄变成 `g`——这个 bug 很隐蔽，先写测试再写实现。
2. **文本位置**：任务书 §5 的示例里，`box` 在 `120 100 160 60` 时文本是 `(140,135)`，不是矩形中心。按 `phase_cli_1.md` §4.4 的原文来；拿不到原文就按这个示例反推（左内边距 20、上内边距 35）并写进 ADR。
3. **`box` 的 `tree` 摘要**：容器行只显示 `box#n1`，别把子节点摘要拼上去，否则树格式和示例不一致。
4. **`read` 的降级不能只靠 `try/catch`**：缺子部件的 box 要么整体拒绝、要么整体降级成 `g`，不许留下"半个 box"。
5. **六图形迁移要一个一个来**，每迁一种跑一次 `npm test`。一次性搬完再跑，红了很难判断是 `svgAttributes` 顺序错了还是 `hasTextContent` 漏了。
6. **插件包里不要 `import` 其它插件**，只依赖内核公开的接口和 `src/domain/` 的类型。
