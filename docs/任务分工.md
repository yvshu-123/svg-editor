## 3. 第二部分：CLI 插件式重构

### 3.1 内核（农权淳）

| 任务 | 内容 | 验收要点 |
|---|---|---|
| 四个扩展点接口 | `ShapeProvider`、`Command`、`TreeDecorator`、`AttributeHandler`，定义在内核一侧 | 内核只依赖接口，不 import 任何具体图形/命令 |
| 注册表与插件上下文 | 按「类别 + 名字」登记，重复即报错；`createPluginContext()` 提供注册、文档、事件、事务 | 四接口各有一个最小示例插件可注册并执行 |
| 按名分派改造 | `CommandRegistry`、`ShapeFactory` 的 Map 改为注册表；`help` 由注册表组装 | `help` 与 Phase 1 输出一致；插件命令能出现在 `help` 里 |
| `set` 三级回退 | handler 命中 → 执行；未命中 → 原属性白名单；都没有 → `unknown attribute`；handler 抛错回滚且不转默认 | 矩形 `fill` 仍走原规则；box 的 `label` 走处理器 |
| 事务回滚 | `SnapshotCommand.execute` 失败时 `restoreFrom(before)` 后原样抛出 | 改一半抛错后，文档与 undo/redo 历史均为执行前状态 |
| 内核钩子 | 命令声明 `requiresDocument`；`data-kind` 读写；文档变更事件；`Shape.onDetach` | `dir` 无文档可用；box 读回与子部件保护可用 |
| 组合根 | `ctx → activate 内置插件 → 可选按配置加载` | 方式 A 只改这一个文件 |
| 扩展点清单 | 接口名、职责、内核调用位置（文件 + 函数）、缺省行为、违约报错 | 每条都能指到真实文件与函数 |

**自验**：`npm run typecheck && npm test` 全绿（基线 188 个测试只增不改）；`SVGFRAME_PLUGINS=none npm run cli < doc/transcript/cli-1.txt | diff - doc/transcript/cli-1.expected` 为空；`rg -n "box|stats|plugin-" src/kernel src/cli` 无具体插件名。

### 3.2 图形插件（张杰）

| 任务 | 内容 | 验收要点 |
|---|---|---|
| 六图形插件化 | `rect/circle/ellipse/line/text/g` 各成独立插件包，含 `svgAttributes` 顺序与文本内容标记 | 迁走后 Phase 1 全会话输出逐字节不变 |
| `box` 图形 | 容器，子节点 `<id>-rect` + `<id>-label`；`create box n1 120 100 160 60 "开始"`；支持 `in`、整体 `move/scale`、可嵌套；`ungroup` 拒绝 | box 会话完整复现；`tree` 层级正确 |
| `box` 边界 | 子部件 id 预检（冲突整条失败、不留残骸）；`data-kind="box"` 序列化；未装插件读回降级为 `g`；缺子部件/类型错拒绝或降级（ADR 定一种）；`delete`/`move` 拒绝移走必要子部件 | id 冲突后 `tree` 与创建前一致；装/不装读回都不崩 |
| `box` 属性处理器 | `fill` → 内部矩形；`label` → 内部文本；每条 `set` 一个 undo 单元 | 各一次 undo 整体恢复、redo 整体重做 |
| ADR 与测试 | id 派生与读回降级取舍；独立测试（测试替身 context，不依赖其他插件） | `git diff C^ C -- src/ ':(exclude)plugins/shape-box'` 为空 |

**自验**：`npx vitest run plugins/shape-box` 全绿；box 会话回放；`set n1 fill`、`set n1 label` 的 undo/redo 各一次。

### 3.3 命令与标签插件（殷放）

**命令**

| 任务 | 内容 | 验收要点 |
|---|---|---|
| `stats` | 从画布子节点 DFS；叶子按类型计数、类型按首现序；`g`/`box` 只计 containers，根不计；空文档 `(total 0, containers 0)`；自带 help；不进 undo 栈 | 输出与示例一致；执行后 undo 栈不变 |
| 目录访问接口 | `DirectoryLister.list(path): DirEntry[]`（或给 `FileSystemPort` 加 `list`），适配器模式的目标接口 | 命令逻辑不直接依赖 `node:fs` |
| `NodeDirectoryLister` | `readdirSync({ withFileTypes: true })` 适配为 `DirEntry`；符号链接不跟随、归 `[FILE]` | 真实目录测试通过 |
| `dir` | 0 参数；`[DIR]`/`[FILE]` + 两空格；目录前、文件后，各组按名升序（码点比较）；含隐藏项、不含 `.`/`..`；空目录 `(empty directory)`；失败 `error: cannot read directory: <path>` | 排序稳定、两次输出逐字节一致 |
| `dir` 不入文档 | 不改 dirty、cwd、undo/redo；未 `init` 也可用 | 执行前后 `canvas`/`tree`/undo 均不变 |

**标签**

| 任务 | 内容 | 验收要点 |
|---|---|---|
| `modified-star` | 装饰器实现；状态放实例字段（不用模块级变量）；订阅变更与保存事件 | 编辑后加 `*`，保存后消失 |
| dirty 语义 | 二选一并写 ADR：内容与上次保存不一致（undo 回保存点 `*` 消失）/ 发生过编辑命令（undo 不消失）；新建节点是否立即标记 | 与 ADR 一致 |
| `(box)` 标签 | `kind === 'box'` 的行追加类型标注，不感知 `*` | 与 `*` 同行时顺序符合 ADR |
| 多标签与祖先传播 | 拼接顺序 ADR；改子图形时容器行是否加 `*` | 两标签互不感知 |
| 状态机测试 | 编辑 → 保存 → 再编辑 → undo 回保存点，四分支 | `npx vitest run plugins/tree-star` 全绿 |

**自验**：替身 5 类场景（混合/空/隐藏/读失败/稳定排序）+ `mkdtempSync` 真实目录；不装标签时 `tree` 与 `final` 逐字节一致；只装一个/两个/都不装三种情况正确。

### 3.4 装配与判据（陈智凯）

| 任务 | 内容 | 验收要点 |
|---|---|---|
| 加载器 | 读 `plugins.config.json`，按序 `import()`；相对路径以配置文件目录为基准；包名走 Node 解析；`enabled:false` 跳过；`options` 透传 | 接入新插件不需要改加载器代码 |
| `contributes` 校验 | `shapes`/`commands`/`decorators`/`attributes` 四类名称集合，声明与实际注册逐类比较，缺省为空 | 声明与注册不一致时报错 |
| 失败与回滚 | `plugin not found` / `plugin has no default export` / `plugin manifest mismatch` / `plugin failed to activate` / `duplicate registration: <category>/<name>`；失败撤销该插件全部暂存注册，继续加载且不退出 | 五类文案逐字一致；回滚后 `help` 无残留 |
| 配置装配 | `--config <path>`；非法配置 `error: invalid plugin config`，以内置能力启动 | 坏 JSON 下仍能 `init` + `create` |
| 双装配一致性 | 同一会话分别用代码装配与配置装配执行，输出逐字节相同 | `diff` 为空；基础兼容性比较时禁用新增插件对照 `final` |
| 判据脚本 | `scripts/verify/`：禁插件回归、双装配 diff、`git diff` 判据、加载器失败 | 一条命令跑完全部判据 |
| 指标脚本 | `scripts/metrics/`：文件清单与职责、行数按内核/装配处/插件拆分、圈复杂度增量（`final` vs `p2`） | 删掉产物重跑，数字复现 |

**自验**：`git diff C^ C -- src/ ':(exclude)plugins/<新插件>'` 为空（先 `ls` 确认路径存在）；`rg -n "import|require|switch" src/host/` 无硬编码插件导入与分支；`docs/metrics/` 重跑一致。
