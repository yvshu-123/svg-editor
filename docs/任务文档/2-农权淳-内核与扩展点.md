# 任务文档 · 农权淳 · 第二部分：内核与扩展点

> 分支 `feat/kernel`｜提交前缀 `feat(kernel):`
> 一句话：把 Phase 1 的两处 `Map` 分派改造成注册表，定义四个扩展点，让后续插件只依赖接口。

Phase 1 现状（都是你要改的地方）：

| 文件 | 现状 |
|---|---|
| `src/index.ts` | 组合根：`new` 出所有实现、最后 `repl.start()`，39 行 |

## 5. 容易踩的坑

1. **`help` 的逐字节一致**是硬指标。`HELP_LINES` 里有大量手工对齐的空格，改成插件后如果重新格式化就会差几个空格，直接判失败。做法：把每行原文切到各插件的 `help` 字段里，不要重新排版。
2. **`SnapshotCommand` 的 try/catch 不能吞异常**：`restoreFrom` 之后必须原样 `throw`，否则 `CommandHistory.execute` 会把失败当成功、推入 undo 栈。
3. **`Repl.dispatch` 现在按名字特判 `init/read/help`**，改成 `requiresDocument` 后要确认 `undo/redo` 仍然要求有文档（它们不走 registry）。
4. **六图形迁移必须在 D4 前完成**（张杰负责），否则「禁插件仍能跑 Phase 1」这条你没法验证——D2 起每天和他对一次进度。
5. **复合图形依赖 `Document.add` 的原子性。** 当前 `collectIds()` 会边查重边写索引，后续子节点冲突时，已登记的 ID 可能残留。按 §6.4 验证并修正这处行为。
6. **别在 `src/kernel/` 里写 `if (kind === 'box')`**。任何类型特判都要变成接口方法（比如 `canUngroup`），否则第 1 节判据直接不过。

## 6. 分步实现与验收规格

按一次能从 CLI 验证的改动推进。首个切片选 `tree`，其余内置能力分批迁移。现有命令实现、快照和历史管理优先复用。每步的验收覆盖原任务要求，具体类拆分和方法命名按实现需要决定。术语见 [项目术语表](../../CONTEXT.md)。

### 6.1 固定 Phase 1 基线（K9）

- 从 `final` 记录 `help` 原文和旧会话的 CLI 标准输出。会话以 `tests/acceptance/transcript.test.ts` 为依据，用同一个工作目录和输入文件跑前后两版。
- `cli-1.txt` 只写命令和 `#` 注释。`cli-1.expected` 以实际管道回放的标准输出为准，逐字节比较标题、提示符、空格和换行。分别跑旧验收断言和 §3 的管道 `diff`。

### 6.2 先迁移 `tree`，再迁移内置命令（K1–K4、K7）

- **首个切片。** `index.ts` 把 `tree` 注册进上下文，CLI 按名取得命令声明并构建现有 `TreeCommand`。依次执行 `init 800 600`、`create rect bg 0 0 800 600 #ffffff`、`tree`，与 `final` 逐字节比较。另起会话直接执行 `tree`，仍应报 `error: no document. use 'init' or 'read' first`。
- **全部迁移。** 16 条命令都通过注册表分派。保留旧参数校验顺序、报错和撤销语义。未初始化时验证 `help` 可用、`undo` 与 `redo` 仍要求文档，再用一个最小命令插件验证它可以声明无需文档。
- **帮助。** `HelpComposer` 使用已注册命令的帮助信息。内置分组、公共说明、顺序和空格以 `final` 为准。最小命令插件启用时能执行且其帮助追加在末尾，未启用时帮助中无该项，执行报未知命令。

### 6.3 交付加载器需要的注册接口（K2，依赖 §6.2 的最小注册接口）

- 四类贡献分开登记。用同一类别的重名验证 `duplicate registration: <category>/<name>`，同名但类别不同可以共存。
- 每次激活使用独立的暂存区。加载器能查询本次各类别登记的名字，以及当前已提交的名字。激活和声明校验成功后提交，失败则丢弃本次暂存。用一次激活先成功暂存命令、随后遇到重名的场景验证，`help` 与分派只能看到提交成功的条目。
- 这部分可与内置命令迁移并行。按 §4 在 D3 向陈智凯交付契约。加载器的动态导入、配置校验和错误分流按其任务文档落地。

### 6.4 接入图形扩展和结构钩子（K1、K3、K7）

- 和张杰对接 `ShapeProvider`，逐种把六种基础图形的构建规则接入注册表。旧 `create` 参数和错误、普通 SVG 的 `read → tree → save` 输出与基线一致。
- 用一个保存为 `<g data-kind="…">` 的扩展图形验证读回。启用对应插件时能还原扩展图形，未启用时能读为普通 `g`。已启用但结构无效时，按张杰的 ADR 验收。
- 验证必要子部件的删除和移出会被拒绝。拒绝后检查树和 ID 索引。复合图形允许整体移动，并可拒绝 `ungroup`。单独平移必要子部件的行为按 §6.7 对齐。
- 直接调用 `Document.add()` 添加含冲突子节点的子树，验证失败后根节点和之前遍历到的子节点 ID 都未登记。该用例直接检查文档，避免命令层的快照掩盖索引残留。

### 6.5 接入属性处理、树标签和文档通知（K1、K5–K7）

- `set` 命中处理器时由它修改文档，未命中时调用图形原有属性规则。验证普通矩形可以改 `fill`、扩展属性可以写入和撤销、未知属性保留原报错。
- 用一个处理器先修改文档再抛错。验收文档内容、undo 和 redo 栈深度都与执行前一致，并能看到原始错误。选一个已有 redo 记录的场景，确认失败命令没有清掉它。
- 用最小标签验证单行树输出可扩展。无标签时逐字节匹配 `final`。与殷放对齐通知契约，至少能覆盖成功编辑、撤销、重做以及成功保存后更新保存点。失败并回滚的编辑不应触发变更通知。

### 6.6 合并装配与验收（K8–K10）

- `index.ts` 装配内置命令和六种基础图形，并把 `--config` 交给加载器。禁用 Phase 2 新增插件时，复跑 `final` 会话，基础命令和图形仍可用，标准输出 `diff` 为空。
- 跑 `npm run typecheck && npm test`，核对旧验收断言、四类最小插件和 §3 的内核边界检查。按 §2 K10 把真实调用文件和函数写入 `doc/parts/kernel.md`。

### 6.7 待确认的行为

**直接平移必要子部件。** 图形任务的验收示例要求拒绝 `move n1-rect 10 10`。当前 `MoveCommand` 只改变坐标，结构钩子 `onDetach()` 覆盖的是删除或换父容器。建议按示例同时拒绝直接平移和移出。若允许单独平移，需要和张杰同步更新验收。该选择只影响图形钩子契约，命令迁移可先推进。
