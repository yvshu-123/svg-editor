> 分支 `feat/host`｜提交前缀 `feat(host):` / `chore(metrics):`
> 一句话：写插件加载器（配置装配）、把失败与回滚做干净、把全部判据脚本化，再产出指标。

## 0. 上下文

```bash
git clone https://github.com/yvshu-123/svg-editor-lab1.git
cd svg-editor-lab1 && git checkout -b feat/host final
npm ci && npm test        # 188 个测试全绿 = 基线
```

现状：`src/index.ts` 是组合根（39 行），所有实现都是 `new` 出来手工接的；仓库是**单包**，没有 workspace，`npm run cli` 直接 `tsx src/index.ts`。

**边界**：加载器属于**装配侧**，不是内核。它可以用字符串模块名去 `import()`，但**不许出现任何具体插件的导入、名称映射或条件分支**。

## 2. 任务

| # | 任务 | 内容 | 完成标准 |
|---|---|---|---|
| H1 | 加载器主体 | 读配置 → 按数组顺序 `import()` → 调 `activate(ctx, options)`。相对路径以**配置文件所在目录**为基准（`pathToFileURL(resolve(dirname(config), m))`）；包名交给 Node 解析；`enabled:false` 完全跳过；`options` 原样透传 | 加一个插件只改配置、不改加载器代码 |
| H2 | `contributes` 校验 | 四类名称集合（`shapes`/`commands`/`decorators`/`attributes`，缺省视为空），把声明与实际注册逐类比较 | 声明多了/少了都能报出来 |
| H3 | 失败与回滚 | 见下表六种情况；任一失败撤销该插件的**全部暂存注册**，保留已成功的插件，继续加载后面的，主程序不退出 | 六条文案逐字一致；回滚后 `help` 里看不到残留 |
| H4 | 配置入口 | `--config <path>`；配置语法/结构不合法 → `error: invalid plugin config`，然后以默认内置能力启动 | 坏 JSON、`plugins` 不是数组、模块项缺 `module` 三种情况都能启动 |
| H5 | 双装配一致性 | 同一份会话、同一目录、同样插件集合与顺序，分别用（A）默认代码装配、（B）`--config` 执行，输出逐字节相同 | `diff` 为空；基础兼容性比较时禁用全部新增插件对照 `final` |
| H6 | 判据脚本 | `scripts/verify/all.sh`：禁插件回归、双装配 diff、`git diff` 判据、加载器失败场景、`tree` 基线 | 一条命令跑完，非零退出即失败 |
| H7 | 指标脚本 | 从 git 历史抽取 `final` 与 `p2` 两个 ref；输出文件清单与职责、行数按「内核 / 装配处 / 插件」三类拆分、圈复杂度增量；排除 `node_modules` 与构建产物 | `docs/metrics/` 删掉后重跑，数字完全复现 |

### 六种失败必须逐字命中（判分点）

| 情况 | 输出 |
|---|---|
| 模块找不到 | `error: plugin not found: <module>` |
| 没有默认导出 | `error: plugin has no default export: <module>` |
| 声明与实际注册不一致 | `error: plugin manifest mismatch: <name> (declared: …, registered: …)` |
| `activate` 抛错 | `error: plugin failed to activate: <name> (<reason>)` |
| 同名重复注册 | `error: duplicate registration: <category>/<name>` |
| 配置本身不合法 | `error: invalid plugin config` |

注意：**模块存在但求值失败**（依赖缺失、语法错误）属于"加载失败"，不能报成 `plugin not found`。

## 3. 自验清单

- [ ] 配一个不存在的模块名 → `error: plugin not found: xxx`，程序继续运行，`help` 正常
- [ ] 配一个没有 `export default` 的模块 → `error: plugin has no default export: xxx`
- [ ] 让插件声明 `shapes: ["box"]` 但实际不注册 → `error: plugin manifest mismatch: ... (declared: box, registered: )`
- [ ] 让 `activate` 里 `throw new Error('boom')` → `error: plugin failed to activate: xxx (boom)`
- [ ] 两个插件抢同一个命令名 → 后者 `error: duplicate registration: commands/xxx`，且它的其余注册全部消失
- [ ] `plugins.config.json` 写成坏 JSON → `error: invalid plugin config`，随后 `init` + `create` + `save` 都正常
- [ ] `enabled:false` 的插件完全不加载（`help` 里没有、也不报错）
- [ ] `npm run cli < doc/transcript/cli-1.txt` 与 `npm run cli -- --config plugins.config.json < doc/transcript/cli-1.txt` 输出 `diff` 为空
- [ ] `rg -n "import|require|switch" src/host/` 里没有具体插件名，再人工通读一遍
- [ ] `git diff C^ C -- src/ ':(exclude)plugins/<新插件>'` 为空；**先 `ls` 确认路径存在**（路径写错时空输出是假通过）
- [ ] 删掉 `docs/metrics/` 重跑脚本，数字一致；三类行数之和与总行数对得上
- [ ] `scripts/verify/all.sh` 从干净 clone 跑通

## 5. 容易踩的坑

1. **别用 `require` 或写死的 `import` 表**：ESM 下就是 `await import(specifier)`；相对路径必须先转成 `file://` URL，Windows 上尤其明显。
2. **暂存注册不是"先注册再删"**：如果先真正注册再清理，期间 `help` 已经能看到、并发命令可能真的执行了。要内核提供"暂存区"，激活成功才提交。
3. **比较"声明 vs 实际"时，实际注册要看这个插件自己注册了什么**，不是全局表——否则前一个插件注册的东西会算到后一个头上。
4. **`git diff` 判据要分两次看**：第一次确认路径存在（`ls <内核目录>`），第二次才看 diff；文档里已经提醒过，空输出不等于通过。
5. **双装配比较时注意目录内容**：把 `dir` 的输出也算进会话时，日志文件别写进被列的目录，否则第二次跑就多一个文件。
6. **指标脚本别 `git add` 产物后就地重跑**：脚本要能对任意两个 ref 运行，数字完全由脚本算出，不允许手改 `docs/metrics/` 里的表。
